# Проект: ETL-пайплайн витрины платежей Яндекс Такси

**Стек:** Airflow · PySpark · S3 (Yandex Object Storage) · ClickHouse · Yandex DataProc

## Задача

Построить автоматический ETL-пайплайн, который ежедневно агрегирует данные о поездках такси по способам оплаты и складывает витрину в ClickHouse. Витрина становится источником для финансовых отчётов и аналитических дашбордов.

Каждый день пайплайн:

1. дожидается появления свежего файла с данными в S3;
2. запускает Spark-задачу на кластере DataProc;
3. рассчитывает по каждому способу оплаты четыре метрики;
4. пишет итоговую таблицу `taxi_payment_summary` в ClickHouse.

## Архитектура

```
S3 (parquet) ──> S3KeySensor ──> DataprocCreatePysparkJobOperator ──> PySpark-джоб ──> ClickHouse
   raw data      проверка файла        запуск задачи на кластере        агрегация        витрина
    (Airflow DAG orchestrates the pipeline daily)
```

## Метрики витрины

Группировка — по полю `payment_type`:

| Метрика | Выражение | Что показывает |
|---|---|---|
| `n_of_rides` | `count(*)` | общий спрос и загрузка сервиса |
| `avg_fare` | `avg(fare)` | средний чек поездки |
| `avg_tips` | `avg(tips)` | удовлетворённость клиентов, мотивация водителей |
| `total_income` | `sum(trip_total)` | суммарная выручка компании |

## Структура проекта

```
etl-taxi-payment/
├── README.md
├── spark/
│   └── my_spark_job.py                  # Spark-джоб: чтение parquet, агрегация, запись в ClickHouse
└── dags/
    └── taxi_payment_warehouse_dag.py    # DAG: расписание, сенсор S3, запуск Spark-задачи
```

- **`my_spark_job.py`** — сам обработчик: Spark-сессия, чтение parquet из S3, агрегация четырёх метрик по `payment_type`, запись результата в ClickHouse через JDBC-драйвер.
- **`taxi_payment_warehouse_dag.py`** — оркестратор: ежедневный DAG с `S3KeySensor` (проверка наличия файла раз в 5 минут, таймаут час) и запуском Spark-джоба с кластера DataProc.

Разделение «что делаем» (Spark) и «когда делаем» (DAG) — базовый принцип ETL-проектирования: джоб ничего не знает о расписаниях, DAG — о деталях трансформации.

## Как это работает

Пайплайн исполняется на управляемой учебной инфраструктуре Яндекс Облака: приватный бакет Object Storage, кластер DataProc, управляемый ClickHouse и Airflow. Вне этой инфраструктуры код не запускается — так же, как продакшн-ETL привязан к своему окружению. Репозиторий показывает архитектуру пайплайна и код: DAG, Spark-трансформации и запись витрины.

Доступы к инфраструктуре вынесены в переменные окружения (`CLICKHOUSE_HOST`, `CLICKHOUSE_USER`, `CLICKHOUSE_PASSWORD`) и не хранятся в коде.
